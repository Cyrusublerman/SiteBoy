# SiteBoy CSS Architecture - Modular System

## Overview

SiteBoy now uses a **modular CSS architecture** instead of a single monolithic stylesheet. This provides better organization, maintainability, and selective loading capabilities.

## File Structure

```
assets/css/
├── index.css          # Main entry point - imports all modules
├── base.css           # Core foundation (variables, typography, resets)
├── components.css     # UI component styles (forms, buttons, dropdowns)
├── layout.css         # Page layout and responsive behavior
├── tools.css          # ToolBase and interactive component styles
├── utilities.css      # Utility classes and debugging tools
└── styles.css         # Bundled version (generated by build script)
```

## Usage

### Development (Recommended)
Use `index.css` for development - it imports all modules modularly:

```html
<link rel="stylesheet" href="assets/css/index.css">
```

### Production
Use `styles.css` for production - it's a bundled version:

```html
<link rel="stylesheet" href="assets/css/styles.css">
```

### Selective Loading
Import only specific modules if you need fine-grained control:

```html
<!-- Core only -->
<link rel="stylesheet" href="assets/css/base.css">

<!-- Add components -->
<link rel="stylesheet" href="assets/css/components.css">

<!-- Add tools for interactive pages -->
<link rel="stylesheet" href="assets/css/tools.css">
```

## Module Descriptions

### `base.css` (130 lines)
- VGA color palette and CSS variables
- Global resets and typography system
- F-system variables and theme definitions
- Utility classes (`.hidden`, `.sr-only`)

### `components.css` (1451 lines)
- All UI component styles
- Form elements, buttons, dropdowns
- Interactive elements and states
- Component-specific styling

### `layout.css` (134 lines)
- Page layout structures
- Grid systems and containers
- Responsive breakpoints
- Navigation and header layouts

### `tools.css` (165 lines)
- ToolBase component styles
- Canvas area styling
- Sidebar layouts
- Tab systems and controls
- Fullscreen overlays

### `utilities.css` (718 lines)
- Specialized component styles (TOC, galleries)
- Debug utilities and development tools
- Scrollbar styling
- Mathematical validation styles

## Build System

### Automatic Bundling
Use the build script to create a bundled version:

```bash
./scripts/bundle-css.sh
```

This creates `assets/css/styles.css` by concatenating all modules.

### File Watching (Future)
Consider adding a file watcher for automatic bundling during development.

## Migration Notes

### From Monolithic to Modular
- The site automatically uses the modular system
- All existing styles preserved
- No breaking changes to existing code

### Inline Styles → CSS Classes
As part of the ToolBase refactoring, inline styles should be moved to `tools.css`:

```javascript
// ❌ Bad - Inline styles
element.style.cssText = `height: ${this.F * 2}px; padding: ${this.F}px;`;

// ✅ Good - CSS classes
element.className = 'tool-control tool-button';
```

## Architecture Rules

### ✅ **DO**
- Keep styles organized by concern
- Use CSS variables for dynamic values
- Follow F-system for sizing
- Maintain VGA color constraints

### ❌ **DON'T**
- Add styles to monolithic `styles.css` (use appropriate module)
- Use inline styles (move to CSS classes)
- Break color/font constraints
- Add monolithic styles to modules
