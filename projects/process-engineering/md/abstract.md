Every tool, generative piece, and library module on this site was produced by a repeatable engineering process — not improvisation. The process begins when a vague creative idea enters the system and terminates when working, tested code is live at a URL and documented. Between those endpoints are seven defined phases: idea capture, process design, Wikipedia-based research, module discovery, gap analysis, build-and-categorise, and page implementation.

The process is agentic: each phase is executed by AI agents operating under explicit procedural constraints, not open-ended prompts. Agents are given bounded authority, defined success criteria, and mandatory source-reading checkpoints. Every mathematical formula is traced from a Wikipedia article through a parsed Markdown corpus to a typed JavaScript function — without breaking the citation chain. Decisions are externalised into version-controlled files so they can be inspected weeks later.

The methodology was developed by working on a specific problem — generating complex line shading using space-filling curves — and generalises to any domain where Wikipedia provides adequate coverage of the underlying mathematics. The result is a shared algorithm library (`blog/ideas/reference documentation/processing/`) of pure functions covering geometry, colour, physics simulation, audio, and image processing, each annotated with source, formula, and Wikipedia link.

This project page documents that process: not the outputs it produces, but the method itself — the decisions made about how to manage AI-assisted development at this scale.
