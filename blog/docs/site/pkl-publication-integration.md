# PKL Publication Integration

## Ownership

SiteBoy renders a public snapshot generated by the private Personal Knowledge Library. SiteBoy does not read the private repository, holds no Library token, and stores no PKL output. Publication is a Library CI action; a SiteBoy commit is not a publication step (todo A8).

## Content origin

`https://content.einoder.net` — R2 bucket `einoder-content` on a custom domain. Library CI is the only writer.

```text
pkl/manifest.json                          current pointer; written last; no-cache
pkl/snapshots/<sha256>/public-graph.json   immutable graph
pkl/objects/<uid>.json                     current objects; stale keys removed
pkl/revisions/<uid>/<n>.json               write-once public history
feeds/rss.xml | atom.xml | feed.json       Library-generated feeds
```

Bucket CORS: `GET`, `HEAD` from `*` (public, credential-free reads).

## Publication rule

Default-deny at both ends.

- Library compiler (`compile_public_graph.py`): a document is a candidate iff front matter has `visibility: public`. A candidate must also have `uid`/`id`, `title`, `object_type`, and `status` ∈ {`active`, `published`}, else compilation fails. Denied roots, object types, document types and `public_role: hidden` veto. Unparseable front matter is not publishable (warning, skipped). Relationship, project, figure, source and citation targets that do not resolve to a public UID are dropped.
- SiteBoy policy (`assets/js/shared/pkl-publication-policy.js`): re-audits the staged graph in Library CI and in the browser provider.

## Library CI sequence

`Cyrusublerman/Library` `.github/workflows/publish-siteboy-public-graph.yml`:

1. compile;
2. dry-run stage + `siteboy/scripts/pkl/validate-public-graph.mjs` (public SiteBoy, sparse read-only checkout);
3. fetch current graph from R2 (`publish_r2_snapshot.py fetch`);
4. material-change detection and optional regeneration;
5. stage revisions (`sync_siteboy_snapshot.py --target <staging>`);
6. if changed: validate staged snapshot; generate feeds (`generate-public-feeds.mjs`, `SITEBOY_PUBLIC_URL`);
7. upload (`publish_r2_snapshot.py publish`): revisions, objects, graph, feeds, manifest last; delete stale objects.

Secrets (Library): `R2_CONTENT_ENDPOINT`, `R2_CONTENT_ACCESS_KEY_ID`, `R2_CONTENT_SECRET_ACCESS_KEY`, `R2_CONTENT_BUCKET`. Absent ⇒ compile and validate only; publication skipped with a warning.

## Browser access

`assets/js/shared/pkl-content-provider.js` reads `https://content.einoder.net/pkl` by default; `VITE_PKL_BASE_URL` overrides it (e.g. `/generated/pkl` for a local staged snapshot, gitignored).

```js
import { pklContentProvider } from '/assets/js/shared/pkl-content-provider.js';

await pklContentProvider.load();
const page = pklContentProvider.getByRoute('/wiki/example');
const results = pklContentProvider.search('example', { objectType: 'concept' });
```

The provider validates the snapshot digest before indexing and exposes only publishable objects.

## Feeds

`/rss.xml`, `/atom.xml`, `/feed.json` on the site are `vercel.json` rewrites to `https://content.einoder.net/feeds/*`. SiteBoy `npm run build` does not generate feeds.

## Routing

```text
/wiki/<slug>
/blog/<slug>
/figures/<figure-uid>
```

## Figure dependencies

Figure libraries are adapter dependencies, not global framework dependencies. Vega-Lite, Cytoscape.js, ELK and Observable Plot should be dynamically imported only by figure types that require them. SiteBoy SVG remains the default editorial renderer.

## Corrections

Corrections belong in PKL source or in the compiler and rendering systems. Objects on the content origin are never edited by hand.
