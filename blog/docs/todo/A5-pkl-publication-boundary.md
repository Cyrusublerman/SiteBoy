**Priority**: P0

**Last touched**: 2026-07-28

## Goal

No PKL object marked private, draft, embargoed or otherwise not-for-publication may appear in the public site, the public graph, or the generated feeds — including via links, backlinks, embedded figures, citations or transitive references.

## Done when

`npm run build` exits non-zero whenever the PKL snapshot contains, or public content references, an object not affirmatively marked publishable, verified by `tests/pkl-publication-boundary.test.js` passing under `npm run test:run`.

## Sub-tasks

- [x] Single-source the eligibility rule (`assets/js/shared/pkl-publication-policy.js`).
- [x] Make the rule default-deny: `status` ∈ {`active`, `published`} required; absence denies.
- [x] Add veto conditions: `visibility` ≠ `public`, boolean veto flags, unexpired `embargoed_until`.
- [x] Fail the build on any ineligible object present in the public graph.
- [x] Fail the build on any reference from public content to an ineligible or absent object (relationships, backlinks, figures, body figure embeds, body route links).
- [x] Fail the build on route, alias or tag/project index entries resolving to an ineligible object.
- [x] Fail the build on private-only field names carried by a published object.
- [x] Redact identifiers in validator output by default; full detail behind `PKL_VALIDATION_VERBOSE=1`.
- [x] Restrict feeds to eligible publications; strip unresolved figure embeds and links to unpublished routes.
- [x] Filter ineligible objects out of every `PKLContentProvider` read path.
- [x] `public/rss.xml`, `public/atom.xml` and `public/feed.json` are build artefacts regenerated by `prebuild`, and are gitignored.
- [ ] Audit the sync workflow in `Cyrusublerman/Library` (not present in this repository).
- [ ] Have the PKL compiler emit an explicit `visibility` field so publication is a decision, not a lifecycle side effect.

## Notes / decisions

- 2026-07-28: Publication was previously default-allow. Every object in the snapshot was published; `status` was carried but never read.
- 2026-07-28: `status` is the marker the compiler already emits, so it is the marker the rule reads. `visibility` is honoured as a hard veto when present so the compiler can tighten later without a schema migration here.
- 2026-07-28: `validate-pkl-siteboy-build.yml` commits build logs into this public repository. Validator output is therefore redacted by default; a violation report would otherwise publish the UIDs of non-publishable nodes.
- 2026-07-28: Current snapshot (13 objects, source commit `bd6704b`) is wholly compliant — 13 publishable, 0 denied, 0 dangling references.
