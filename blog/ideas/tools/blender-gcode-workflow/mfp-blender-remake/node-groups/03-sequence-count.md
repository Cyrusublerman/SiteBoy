# Node Group — `MFP_SEQ_Count`

## Purpose

Calculate the number of sequence tiles generated by the selected MFP sequence model.

## Functional Contract

Given filament count, layer count, base/top layer counts, and a model selector, return the exact tile count expected by downstream grid layout. The group exposes the implementation/documentation conflict instead of hiding it.

## Inputs

| Input | Type | Unit | Domain | Default | Validation |
|-------|------|------|--------|---------|------------|
| Filament Count | Int | count | whole `>=1` | from `MFP_PARAM_PrintProcess` | hard fail if `<1` |
| Layers Per Tile | Int | count | whole `>=1` | from params | hard fail if `<1` |
| Base Layers | Int | count | `0..Layers Per Tile` | from params | clamp before use |
| Top Layers | Int | count | `0..Layers Per Tile` | from params | clamp before use |
| Sequence Model | Int enum | - | `0=valid_stacks`, `1=base_variable`, `2=imported_table` | `0` | unsupported value is invalid |
| Imported Sequence Count | Int | count | whole `>=0` | `0` | required for model `2` |

## Outputs

| Output | Type | Domain | Meaning |
|--------|------|--------|---------|
| Sequence Count | Int | graph | generated tile count |
| Variable Layers | Int | graph | `max(0, Layers Per Tile - Base Layers - Top Layers)` |
| Uses Imported Table | Boolean | graph | `Sequence Model == 2` |
| Count Valid | Boolean | graph | count is positive and finite |
| Model Conflict | Boolean | graph | true when selected model has known doc/implementation parity conflict |

## Required Attributes Read/Written

| Attribute | Type | Domain | Read/Write | Purpose |
|-----------|------|--------|------------|---------|
| None | - | - | - | Scalar count group; sequence attributes are written by lookup/expand groups. |

## Maths / Logic

```text
N = max(1, floor(Filament Count))
L = max(1, floor(Layers Per Tile))
B = clamp(floor(Base Layers), 0, L)
T = clamp(floor(Top Layers), 0, L - B)
V = max(0, L - B - T)

valid_stacks_count =
  if N == 1: L
  else: N * (N^L - 1) / (N - 1)

base_variable_count = N^V
imported_count = max(0, floor(Imported Sequence Count))

Sequence Count = switch(Sequence Model, valid_stacks_count, base_variable_count, imported_count)
Count Valid = Sequence Count > 0
Model Conflict = Sequence Model in {0,1}
```

## Node Composition

```text
Group Input
  -> Floor/Clamp: N, L, B, T
  -> Math(Subtract/Subtract/Max): V
  -> Math(Power): N^L and N^V
  -> Math(Subtract/Divide/Multiply): valid stacks geometric sum
  -> Switch(N == 1): L vs geometric sum
  -> Switch(Sequence Model):
       0 valid_stacks_count
       1 base_variable_count
       2 imported_count
  -> Compare Greater Than 0 -> Count Valid
  -> Group Output
```

## Blender vs Python Ownership

GN can calculate the counts. Python should own exact imported-table count, UI warnings, and any final project decision that removes one model. Sorting and table generation may remain Python-owned for large counts.

## Validation / Failure Modes

- `Sequence Count == 0` cannot produce a grid.
- Large `N^L` may exceed practical GN integer/float precision; Python should preflight high counts.
- `Sequence Model = imported_table` without an imported count is invalid.
- `Top Layers` are included in `Variable Layers` even if current implementation treats them as reserved.

## Parity Notes

`valid_stacks` matches current `generateSequences(N,M)`. `base_variable` matches SOURCE documentation. The default remains `valid_stacks` for current-tool parity until the conflict is resolved.
